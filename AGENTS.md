Guidelines for AI coding agents working in this repository.

## Canonical references

- **`docs/coding_standards.md`** — authoritative coding quality, review, and PR standard. Read it before writing or reviewing code.
- **`CLAUDE.md`** — PR review instructions and design doc conventions (points to `docs/coding_standards.md` for details).

Do not duplicate the content of those files here. This file only covers things an agent would likely miss or guess wrong.

## Repository

- Default branch is **`dev`**. Base all branches and PRs against `dev`.
- **`operator/`** is a separate Go project (Kubernetes operator) with its own `AGENTS.md`, build system, and toolchain. Ignore it when working on the Python library.
- **`lmcache/_version.py`** is auto-generated by `setuptools_scm` from git tags. Never edit it manually.

## Build & Install

```bash
# Standard (CUDA extensions, requires torch + nvcc pre-installed)
pip install -e . --no-build-isolation

# Source-only (no native extensions at all — pure Python)
NO_NATIVE_EXT=1 pip install -e .

# CPU-only (common C++ extensions, no GPU backend)
NO_GPU_EXT=1 pip install -e . --no-build-isolation

# HIP/ROCm
BUILD_WITH_HIP=1 pip install -e .
```

- `NO_CUDA_EXT` is **deprecated**; use `NO_NATIVE_EXT=1` instead (it has always controlled all native extensions, not just CUDA).
- `LMCACHE_CUDA_MAJOR=12|13` selects between `cuda12_core.txt` and `cuda13_core.txt` vendor pins (default: 13). Only matters for `pip install` when `NO_GPU_EXT` is not set.
- `torch` must be installed **before** `pip install -e . --no-build-isolation` because setup.py uses `torch.utils.cpp_extension` at build time.

## Architecture

### Device abstraction

`lmcache/__init__.py` exports `torch_dev` and `torch_device_type` at package load. **Never use `torch.cuda`, `torch.xpu`, or `torch.hpu` directly in `lmcache/`** — a pre-commit hook (`ban-torch-device`) will reject it. Use the exported `torch_dev` / `torch_device_type` instead. Exempted: `lmcache/__init__.py` itself and `gpu_connector/` subdirectories.

### Native ops backend

`lmcache/__init__.py` dynamically merges `python_ops_fallback` with the best available native backend (`lmcache.c_ops` for CUDA, `lmcache.xpu_ops` for XPU). The merged module replaces `sys.modules["lmcache.c_ops"]`. Always `import torch` before importing `lmcache.c_ops` or any native extension module.

### Key entry points (from `pyproject.toml`)

- `lmcache` → `lmcache.cli.main:main`
- `lmcache_server` → `lmcache.v1.server.__main__:main`
- `lmcache_controller` → `lmcache.v1.api_server.__main__:main`

### Package layout

- `lmcache/v1/` — core engine (cache_engine, storage_backend, distributed, multiprocess, gpu_connector, etc.)
- `lmcache/integration/` — adapters for vLLM, SGLang, TensorRT-LLM
- `lmcache/cli/` — CLI commands
- `lmcache/storage_backend/` — legacy (v0) storage backends
- `csrc/` — CUDA/C++ native extensions (built into `lmcache.c_ops`, `lmcache.native_storage_ops`, `lmcache.lmcache_redis`, `lmcache.lmcache_fs`)
- `rust/raw_block/` — Rust raw-block I/O extension (`cargo fmt`, `cargo clippy`)

### Auto-generated files excluded from linters

`lmcache/integration/vllm/lmcache_mp_connector_*.py` is excluded from ruff, mypy, codespell, isort, and pre-commit. Do not lint or manually edit these files.

## Testing

```bash
# Standard test suite (mirrors CI)
pytest -xvs \
  --ignore=tests/disagg \
  --ignore=tests/v1/multiprocess/ \
  --ignore=tests/v1/distributed/ \
  --ignore=tests/skipped \
  --ignore=tests/v1/storage_backend/test_eic.py

# Single test
pytest -xvs tests/v1/test_cache_engine.py::test_function_name
```

- Test deps: `uv pip install -r requirements/test.txt`
- `@pytest.mark.no_shared_allocator` disables the shared-allocator monkeypatch for a test.
- Test files mirror the source structure under `tests/` (e.g., `lmcache/v1/cache_engine.py` → `tests/v1/test_cache_engine.py`).

## Linting & Code Quality

```bash
# Run all checks (mirrors CI)
pre-commit run --all-files

# Individual tools
ruff check .                          # E, F, B, SLF rules
ruff format .                         # line-length 88
isort .                               # black profile, from_first=true
mypy --config-file=pyproject.toml
codespell --toml=pyproject.toml
```

- C++/CUDA: clang-format (Google style, 80-col, `.clang-format` in repo root).
- Rust: `cargo fmt` and `cargo clippy — -D warnings` (in `rust/raw_block/`).
- Lint deps: `pip install -r requirements/lint.txt`

### Key enforced rules

- **SPDX header**: `# SPDX-License-Identifier: Apache-2.0` must be the first line of every `.py` file (pre-commit hook: `check-spdx-header`).
- **Import ordering**: Section-heading comments required — `# Standard`, `# Third Party`, `# First Party`, `# Local`. Managed by isort (see `.isort.cfg`).
- **SLF (private member access)**: ruff SLF rule is enforced by CI **only** in `lmcache/v1/multiprocess/` and `lmcache/v1/distributed/` (per-file-ignores in `pyproject.toml`). Project-wide standard: never access `_`-prefixed members of other classes, regardless of directory.
- **No `assert` for runtime validation**: Use `if …: raise ValueError(…)` instead. Assertions are stripped by `python -O`.
- **No boolean parameters**: Use enums or split into separate functions.
- **Use `init_logger(__name__)`** from `lmcache.logging`, not bare `logging.getLogger()`.

## Documentation

- **Design docs** (`docs/design/`) **mirror the `lmcache/` package tree**: `lmcache/<path>/` → `docs/design/<path>/`. See `docs/design/README.md`.
- **Module READMEs** stay co-located with code; they are symlinked from `docs/design/<path>/README.md`. Do not move them.
- **User docs**: `docs/source/` (reStructuredText, Sphinx). New pages must be linked from a `toctree`.
- **Build docs**: `pip install -r requirements/docs.txt && cd docs && make clean && make html` (must complete without errors or warnings).
